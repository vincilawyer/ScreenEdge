# 通用控制边缘读取记录

日期：2026-09-12。实测系统：macOS 26.6.2，Apple Silicon。

## 发现

系统显示器设置使用 UniversalControl 私有框架。其基本 XPC 协议 `UniversalControl.UniversalControlXPCBasicInterface` 提供 `xpcGetEdgesWithCompletion:`，连接系统服务 `com.apple.ensemble` 可取得当前本机通用控制边缘。

本应用只调用该读取方法。不请求管理接口，不改动键鼠转发、连接状态、屏幕排列或系统偏好。应用以普通登录用户运行，无特殊 entitlement，不需要辅助功能或屏幕录制授权。

响应为 `UniversalControlXPCEdgeRegion` 安全编码对象数组。通过它的 `encodeWithCoder:` 取得键 `UniversalControlEdgeRegion` 对应的数据，解析属性列表或 JSON，使用以下字段：

- `id.display`：本机显示器 UUID，与 CoreGraphics 显示器标识匹配。
- `edge`：`left`、`right`、`top`、`bottom`。
- `rect`：`[x, y, width, height]`，通道在 CoreGraphics 全局桌面坐标系下的细矩形；y 向下增长，上方的外屏可有负 y。

仓库不保存真实设备 UUID、设备名称、系统归档或原始诊断输出。

## 转换与降级

根据 UUID 定位 NSScreen 和 CGDisplayBounds，用后者的全局原点把通道转换为屏幕局部坐标，验证矩形位于声明的屏幕边缘，再裁剪到屏幕尺寸。上下边沿 x 轴；左右边把局部左上坐标转换为 AppKit 的左下坐标。未知屏幕、非有限数值、无效长度、位置不兼容的数据均不绘制。

每约 3 秒读取一次。读取超时为 3 秒，回调最多生效一次。新的快照替换旧结果；失败和空结果清除旧通道。关闭自动识别会清除结果，并用请求代数忽略旧请求的迟到回调。

私有接口可能随 macOS 版本变化。动态加载和 Objective-C 异常处理使接口缺失或编码变化回落为可读状态提示，不影响扩展屏和手动标记。

## 实测边界

已在一台 Mac、一个已连接的通用控制通道上，验证读取、显示器匹配、上边缘范围和真实窗口绘制；外接屏接入后，外屏上边缘也通过同一项检查。空结果、读取错误通过应用内部注入验证清除逻辑；不等同于已实测设备断连重连。

四个方向和非零屏幕原点由合成数据测试覆盖。研究过程中实际布局从单屏变成双屏，通用控制通道移动至上方外屏：由此确认接口返回的是全局 Quartz 坐标，并增加负 y 与偏移 x 的回归测试。

当前接口只用于取得本机通道，没有取得远端对应区间或远端光标位置。两台 Mac 同时运行时可各自显示边缘，但真实出入口是否与归一化渐变完全一致，需要两端验证。不能把本机查询成功当作双端映射已验证。iPad 不能运行此 macOS 程序。

## 1.2.0 预览中的对端

基本接口仍只读取本机入口。`DisplayMapGeometry` 为每个有效入口生成独立的对端示意卡片，放在入口方向，以虚线连接真实入口中点；尺寸为绘图所用的估计值。卡片明确标记为非实际比例，不计入本机屏幕、不进入覆盖层模型，也不作为远端设备数量。断开、读取失败或关闭通用控制标记时，卡片随入口一同消失。
